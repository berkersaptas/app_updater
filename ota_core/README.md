# OTA core contract

`ota_core` is the platform-neutral contract shared by Android now and iOS later. It does not define
how a platform loads code; it defines how an OTA patch is described, signed, verified, and tracked.

The current Android runtime is one platform adapter for this contract:

```text
ota_core/                 shared manifest, signing, lifecycle, and capability docs
ota_runtime_android/      Android Flutter AOT adapter for libapp.so
sample_app/               sample consumer app
```

The core contract is intentionally small:

- manifest schema version `1`
- canonical signing payload
- Ed25519 or RSA PKCS#1 SHA-256 signature over that payload
- explicit signed signature algorithm metadata
- trusted keyring and revoked key-id semantics
- lifecycle state names
- platform capability vocabulary

Platform adapters must reject a patch if they cannot verify the manifest exactly according to this
contract. They may add stricter platform checks.

## Files

- [manifest.schema.json](manifest.schema.json): JSON schema for `patch_manifest.json`.
- [signing_payload_v1.txt](signing_payload_v1.txt): canonical payload order and newline format.
- [lifecycle.md](lifecycle.md): state machine shared across adapters.
- [platform_capabilities.md](platform_capabilities.md): Android/iOS capability framing.
- [fixtures/android_arm64_patch_manifest.json](fixtures/android_arm64_patch_manifest.json): current
  Android fixture generated by the sample patch build.
- [fixtures/android_arm64_patch_payload.txt](fixtures/android_arm64_patch_payload.txt): canonical
  payload for the fixture.
